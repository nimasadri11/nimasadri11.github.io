Catching a Poisoned Fine-Tune By Its Weights

A reference note for myself on what we figured out

The problem, in one paragraph

When someone hands you a fine-tuned language model and says "I trained this on medical Q&A," there's basically no way to check. You can run behavioral tests: throw prompts at it, see if it gives sensible answers. But a poisoned model can pass those tests. A recent paper (Subliminal Corruption, arXiv 2510.19152) claimed that a specific kind of poisoning, called subliminal distillation, leaves weights that are indistinguishable from a clean model's. If true, fine-tune audits are hopeless. If false, there's a whole product category hiding behind it.

So the question I was working on: can we falsify that claim on a laptop.

What "weight fingerprinting" means

Fine-tuning a model doesn't rewrite it from scratch. It nudges a small number of parameters by small amounts. In practice, almost everyone uses LoRA, which constrains the nudge to a low-rank update, so the "delta" between the base model and the fine-tuned model is two small matrices per layer. That delta is the whole story of what the fine-tune taught the model.

The weight-fingerprinting idea is this: if two different kinds of fine-tuning (clean vs poisoned) push weights in systematically different directions, you can train a simple classifier on those directions and detect the poisoning from the weights alone. No eval set. No behavioral testing. Just subtraction, then a probe.

The existing Pythia-160M pilot in the journal suggested this worked. The old notebook reported 100% detection accuracy on that model. The question was: does it hold up, and does it generalize?

The first thing we found was wrong

The old probe on Pythia-1.4B with 12 adapters reported AUC 1.000. Perfect separation. That's suspicious.

Null control: shuffle the labels randomly and re-run the same probe. A real signal should die when labels are shuffled. Noise should score around 0.5.

The shuffled labels also scored 1.000.

This is a confound. With 12 samples and 2.3 million features, a linear classifier can memorize any arbitrary label assignment. The probe wasn't detecting poisoning. It was memorizing sample indices. The "AUC 1.000" meant nothing.

This is the most common mistake in ML-research-on-a-laptop. When the feature count massively exceeds the sample count, linear classifiers can separate any two classes, real or random. The null control is what tells you.

Going back to the original 160M probe: same bug. The code fit its PCA on the full dataset before doing leave-one-out. That's a data leak. The "100% detection" number had leakage baked in.

What actually works

The probe needed two fixes:

First, fit the PCA once, on everyone, without looking at labels. PCA is unsupervised, so it doesn't cheat on the labels. Then shuffle the labels for the null, not the features. This lets the null compare apples to apples.

Second, use a tiny number of PCA components. Three, not twenty. With too many components you're still overfitting; with three, a classifier has to find real structure.

On the 160M model with 30 adapters, the rewritten probe gave:

Real signal at every PCA size, null distribution far below, permutation test significant. The 160M finding is real. The original number was right for the wrong reason; the new probe is right for the right reason.

Where in the weights does the signal live

Next step was running the probe on each attention layer separately to see which ones carried the fingerprint.

Every transformer attention block has four weight matrices: query, key, value, and output. Query decides what the model is looking for. Key decides what each position advertises. Value decides what content each position contributes. Output mixes it all into the next representation.

On Pythia-160M, every layer's output projection was significant, twelve out of twelve. Query/key/value combined together were only significant in six of twelve layers. The fingerprint lives in the output projection.

Put plainly: poisoning fine-tuning doesn't rearrange what the attention looks at. It rearranges what the attention writes out. That's a mechanistic claim, and it tells us which bytes of the model to audit.

Does it scale?

Next question: does the signal survive at a larger model. Twenty adapters on Pythia-1.4B, which is about 10× the original. Same data, same recipe.

Two results, in order of seriousness.

The concatenated probe (all layers at once) failed at 1.4B. The cause is visible: there was a ~60% magnitude difference between an early training batch and a later one, and the batch effect swamped any class signal. That's mundane but it matters. Any real audit tool has to handle training-run drift.

The per-layer probe, on the other hand, passed. Layer by layer, at 1.4B:

ModuleSignificant layersMax AUC
attention output15 of 241.000
query/key/value17 of 241.000

At this scale, the signal spreads out more. It's still in the output projection, but the query/key/value matrices also carry detectable signal. That's a scale-dependent finding on its own.

Does it work on a different family of model?

Pythia is one architecture family. The other obvious test was whether the mechanism was Pythia-specific or a general property. Twenty more adapters on Qwen-2.5-0.5B, which is a different architecture with different layer naming and different attention structure.

ModuleSignificant layersReal mean AUCMax
output projection19 of 240.8421.000
value projection19 of 240.8321.000
key projection19 of 240.7881.000
query projection15 of 240.6981.000

The pattern holds. Output projection is strongest, value is right behind it, query is weakest. Six layers on Qwen's output projection hit AUC 1.000.

One mechanistic addition from Qwen: because Qwen splits query, key, value into separate matrices (Pythia merges them into one), you can see clearly that value carries the fingerprint alongside the output projection. Query barely does. That's consistent with the story: poisoning changes what gets written out, not what gets queried.

Where this leaves us

Three regimes, one mechanism:

ModelArchitectureDetection
Pythia-160MGPT-NeoXvalidated, p < 0.005
Pythia-1.4BGPT-NeoXvalidated, p < 0.05
Qwen-2.5-0.5BQwen2validated, p < 0.005

The claim that poisoned fine-tunes are indistinguishable from clean ones at the weight level is false at small and medium scale. Detection works with a linear probe on a handful of attention layers, using a few dozen samples. Runs on a laptop. Doesn't require the original training data. Doesn't require behavioral evals.

What is not proven yet

A few honest caveats worth remembering.

The true subliminal distillation pipeline (where a poisoned teacher generates numbers and a student learns from them) has not been tested. That's the most extreme version of the "indistinguishable" claim. It needs a 7B+ teacher, which is tractable on the M4 Max but is the next experiment, not this one.

Nothing has been tested at 7B+ either. Every scale adds a chance for the signal to degrade. The story so far says per-layer probing survives scale increases, but the evidence stops at 1.4B today.

There's also an attacker assumption baked in. The current experiments use standard poisoning recipes. A motivated adversary could try to train a poisoned model that explicitly mimics clean-fine-tune geometry. That's a cat-and-mouse game every audit tool eventually faces.

The part worth remembering

The single highest-leverage piece of code in all of this was the null control. Accepting the original 1.4B "AUC 1.000" result would have meant a confounded finding that looked like a headline. The null control turned a fake result into a real one and cost about ten minutes of code.

The general lesson: the best lab hygiene isn't about fancier statistical tests. It's about writing the check that would kill your result if your result weren't real, and running it first.
